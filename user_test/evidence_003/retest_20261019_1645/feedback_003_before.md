# WeightTrend 用户体验反馈表（003）

## 基本信息

- 参与者编号：003。
- 测试日期：2026-10-19（北京时间）。首次执行约 16:06–16:07；T6 补测约 16:09。
- 使用设备：Windows 11，Google Chrome 150.0.7871.127，桌面浏览器视口 1440 × 1000。
- 是否使用过这个界面：本轮使用新的浏览器会话；操作前已阅读指南、源码及既有反馈，不能视为无提示首次使用。
- 输入数据：提供的 CSV 示例档案，以及页面默认模拟体重日志；均不是本人的健康数据。

## T1 导入一份档案

**实际操作：** 展开“导入个人档案（CSV）”，上传示例文件并点击“校验并载入档案”。页面提示校验通过；核对表单身高为 1.70 米、体重为 70.0 千克，并查看当前输入概览。

**体验反馈：** 中文字段、单位和输入概览便于核对，导入后不需要逐项填写。导入入口默认折叠，展开后仍要求 CSV 英文表头和类别编码；本次有明确步骤指引，无法据此判断第一次使用时是否容易找到入口，建议在入口旁提供一行可填写示例。

**单位和来源回答：** 身高单位为米，体重单位为千克；这些数据来自仓库示例，不是个人健康记录。

## T2 运行分析并查看结果

**实际操作：** 保持趋势分析开启、模拟日志不变，每日摄入热量设为 1800 kcal，点击“估计并分析趋势”，查看分类、概率表与图、体重趋势。

**观察结果：** 估计等级为“正常体重”，最高类别概率 47.0%，最高与第二高差值 12.3%；趋势采用日志最新体重 70.5 kg，显示轻度活动、每日消耗估算 2037 kcal、每日能量差 +237 kcal。

**体验反馈：** 分类卡片和能量差能直接提供关键信息，结果旁也说明采用的输入来源。分类概率、特征重要性和趋势分布在较长页面中，查看完整结果需要滚动；建议在结果顶部集中列出分类结论、日志变化和外推假设，并提供跳转入口。

**分类含义回答：** 模型估计的是当前输入所属的肥胖等级；模拟日志趋势和能量平衡外推属于另外的结果。

## T3 阅读结果说明

**实际操作：** 阅读分类附近的概率与适用范围说明，浏览“解释反馈”的特征重要性表，再回到上方展开“数据来源与适用范围”。

**体验反馈：** “概率 80% 不等于患病风险或正确率”和“特征重要性不等于因果解释”直接说明了结果边界，数据来源处也说明了合成数据和适用性限制。特征表仍有 `feature`、`importance`、CH2O、TUE 等英文或缩写，建议改用中文表头，并用短例子解释“中位数填充”和“横断面”。

**理解回答：** 类别概率 80% 不等于个体有 80% 的患病风险，也不是绝对正确率；页面说明尚未验证其他群体适用性，不能据此判断所有大学生的健康状况。

## T4 修改体重后重新分析

**实际操作：** 将档案体重由 70 改为 80 kg，先不分析，查看旧结果提示；随后重新分析并查看“修改前后对比”。

**观察结果：** 提交前出现“输入已修改，请重新分析”，概览变为 80.0 kg，旧分类概率仍为 47.0%。重算后提示消失，等级仍为“正常体重”，最高类别概率降为 32.7%，最高与第二高差值变为 2.0%；对比表显示体重 70.0 → 80.0 kg、概率 47.0% → 32.7%。趋势仍从独立日志的 70.5 kg 起算。

**体验反馈：** 待重算提示能区分当前编辑值和旧结果，前后对比也确实反映本次修改。对比区位于特征重要性表之后，档案体重与日志体重又在不同区块，建议将对比提前，并在结果顶部并列标出两种体重及用途。

## T5 遇到输入错误后恢复

**实际操作：** 将每日摄入热量改为 0 后分析，阅读错误提示；再恢复为 1800 并重新分析。

**观察结果：** 页面说明“每日摄入热量必须为正的有限数值”，该次趋势未生成，分类结果仍保留。恢复 1800 后趋势重新出现，档案体重仍为 80.0 kg，无需重新导入。

**体验反馈：** 错误提示明确指出热量字段，并提供修正重试或取消趋势两条路径，能够继续操作。提示位于结果下部，修正时仍需回到上方输入区，建议提供“返回每日摄入热量”的定位入口。

按题目输入 0 是规定操作，不记作误操作。

## T6 提交反馈并浏览公平性审核

**实际操作：** 选择操作容易程度 3/5，选择“根据当前输入估计的肥胖等级”，填写建议后保存并下载匿名 JSON。切换审核页，依次选择女性、男性、全部群体，再分别查看漏判率 FNR 和误判率 FPR；展开错误率不确定性、下载分组结果，最后返回体重页。

**执行中断与补测：** 首次保存和下载成功，随后在选择“女性”选项时定位超时，未完成后续步骤。另起新会话，重新导入示例、将体重设为 80 kg 并分析后，重新执行完整 T6；使用输入筛选选项并检查选中值，群体、指标切换及返回检查均通过。首次中断的原因尚未确定，本项按补测后完成记录。

**体验反馈：**

- 反馈入口、填写和下载：保存后能看到成功提示，并下载到含评分、答案、建议及分析时间的 JSON。入口位于长结果页末尾，建议增加结果区内的直达入口；“保存”与“下载”是两步，可在成功提示中明确下一步。
- 审核页：两方案并排图表和分组表便于核对，顶部也明确提示本次没有缩小群体差异。但分组表一次展示十三列，F1、TPR、FNR、FPR、EO 等术语密集；建议默认突出样本量、漏判数和误判数，将其他指标放入可展开详情，并将 0.0208 同时解释为约 2.08%。
- 切换与返回：补测同一会话返回后，80.0 kg 档案、1800 kcal 输入、分类结果、趋势及反馈下载入口均保留，符合预期。未测试刷新、关闭或跨会话恢复。

**审核页回答：** 两方案的整体平衡准确率均为 99.26%，EO 差值均为 0.0208，本次约束没有改善该差异。女性组 204 条、漏判 0 次、误判 0 次；男性组 216 条、漏判 2 次、误判 1 次，两方案相同。某组本次零错误不能证明完全公平或未来不会出错；已阅读不确定性说明，本轮没有打开公平性理解自测解释。

## 整体感受

- 操作容易程度：**3/5**。有步骤指引时流程可以完成，长页面中的回看、改错和反馈入口仍需来回定位。
- 结果说明清楚程度：**3/5**。概率边界、数据来源和外推限制明确，但术语、英文表头和信息分布增加阅读成本。
- 最希望优先改进的一处：将结果摘要和修改前后对比集中到结果顶部，直接并列显示“分类采用档案体重 80.0 kg”和“趋势采用日志体重 70.5 kg”，并解释为什么两部分不会同步变化。
- 文字大小、按钮、键盘、小屏幕或输入选项方面的实际困难：桌面操作中的按钮和输入可用；部分辅助文字呈浅灰，重要来源说明可提高视觉权重。使用了焦点、空格和 Enter 完成部分操作，但没有做完整键盘遍历、屏幕阅读器或手机测试，这些体验记为未测试。
- 其他建议：错误提示增加返回输入框入口；审核页先展示少量核心指标。以上是本次操作后的候选改进，本次未修改应用代码。
