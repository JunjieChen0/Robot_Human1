# 新版全流程用户测试指南

适用：2026-10-19 界面版本；不同于旧的体重原型任务单和公平性四题。至少邀请三名同学，统一使用本指南。不要先向参与者解释正确答案。

## 邀请与准备

可复制邀请：

> 想邀请你参加一次约 15–20 分钟的课程界面测试，体验录入、查看结果、修改及反馈。可以全部使用示例数据，无需提供个人健康信息。会匿名记录各任务是否完成、操作时间、错误和理解回答，材料仅用于课程作业；不评价你的健康状况。参与自愿，任何时候都可以退出。

记录者先填匿名编号、日期、Git 提交号与未提交修改情况、设备/浏览器、是否用过旧版或看过参考答案。示例中的体重并非参与者本人的数据。每人独立开始一个新浏览器会话；不要查看前一人的反馈。

安装依赖并运行 `python -m streamlit run app.py`；如果缺少模型，组织者先按 README 生成，安装及训练时间不计入任务时间。向参与者提供 `data/sample/profile_template.csv`。推荐笔记本浏览器，另记录实际屏幕尺寸。有人希望只用键盘时，按原意执行，不替其操作。

## 任务单（给参与者）

每项读完题目后开始计时，到执行终点停表。先记录首次回答再给解释；同一任务超过 5 分钟可询问是否继续或放弃，照实记录，不自动判作成功。

| 任务 | 指令 | 完成终点 |
|---|---|---|
| T1 录入 | 将提供的示例 CSV 导入界面，找到身高、体重单位，并说出它是否属于自己的健康记录 | 正确档案进入表单，并说出“米 / kg”和示例来源 |
| T2 查看 | 执行分析，找到分类结果、体重记录来源和趋势。用自己的话描述分类在估计什么 | 保存首次回答，完成结果查看；操作状态与理解分开记 |
| T3 理解 | 阅读概率与适用范围，回答：某类别概率 80% 是否等于有 80% 患病风险？该结果能否直接说明所有大学生的健康状况？ | 外部记录表保存两题首次回答，不先点页面自测解释 |
| T4 修改 | 将档案体重改为 80 kg。先观察未提交时的提示和结果，再重新分析并查看前后差异 | 识别旧结果提示、重算成功、找到输入/结果比较 |
| T5 恢复 | 将摄入热量改为 0 后分析，读出提示，再恢复 1800 重新分析；也可找到取消趋势的入口 | 不丢失分类结果，趋势重新出现或明确取消；能说明恢复方法 |
| T6 反馈与审核 | 完成理解题和操作难度评分，保存并下载匿名反馈。再切到公平性页，比较女性/男性，说明本次约束有没有改善、零错误代表什么 | 反馈下载；保留首次公平性回答后才查看自测解释，再返回体重页 |

T1 如果参与者选择先手填，允许继续，记录实际路径，但导入动作按未覆盖/部分完成登记。T6 较长，若疲劳可拆分，拆分时间与原因单列，不与未拆分数据直接合并。

## 记录口径

填写 [interaction_records.csv](interaction_records.csv)：每人每任务一行。`completion_status` 使用“完整 / 部分 / 未完成 / 放弃 / 待测”；完成不等于理解正确。`time_seconds` 记录秒表实测，不录入估计数；`timing_method` 写工具及计时范围。提示次数包括口头引导、指向控件或展示答案，页面自己的正常提示不算记录者提示。

`error_count` 只统计可观察事件，例如导入错误文件、错误按钮或重复错误提交，描述写入 `issue`。`understanding_first` 为“正确 / 部分 / 错误 / 无法判断 / 不适用”，原话写入 `answer_verbatim`。提示后回答写 `answer_after_hint`，不能覆盖首次原话。

理解判定点（仅记录者先看）：分类是当前输入的类别估计，概率不等于个体患病风险/绝对正确率，未做外部验证不能推广所有人群；审核页本次两方案没有改善，女性零错误不代表未来没有错误。理解题不要求背诵术语，不根据语言流利程度评分。

## 汇总及复测

按 [迭代说明](interaction_iteration.md) 的规则，分别报告完成、用时、错误与理解，不以完成率代替理解率。每个问题给出观察依据、影响和优先级；修复后至少请发现问题的参与者复测，标明已有使用经历。需要评价首次理解时另邀没有接触材料的人。

可以保留截图或录屏，但应事先征求参与者同意，并避开姓名、聊天信息及个人数据。本仓库自动截图均明确标为自动化示例，不计作真人测试。
